# PS Mobile Wallpaper v1.2.0

这一版把面板**从"打不开、连不上"修到可用**，并给鸿蒙补上了唯一可行的壁纸链路。

## ⚠️ 升级前必读

v1.1.0 是 per-user 安装，可直接覆盖升级。但 v1.0.0 是 per-machine，**不会自动升级** —— 请先卸载旧版。

## 面板：修掉的 4 个致命问题

| 问题 | 根因 |
|---|---|
| 面板**连不上 Bridge**（一直"未检测到设备"） | UXP 的网络权限**只认 `localhost`**，不认 `127.0.0.1` |
| 带认证的请求**全部 401** | 自定义请求头触发 **CORS 预检**，预检不带 Token 被误拦 |
| 导出文件名变成 `xxx.undefined` | UXP 的 `<select>.value` 不像浏览器那样回填 |
| 重开面板就丢设备 | Token 只存内存 |

## 本地认证 Token：改为可选，默认关闭

原本每次重装都要手动复制 Token，而且**一个过期的 Token 和缺失的 Token 表现完全一样**，用户无从判断。

现在 `config.json` 里新增开关，**默认关闭认证**，面板开箱即用：

```json
{ "server": { "host": "127.0.0.1", "port": 18765, "requireToken": false } }
```

需要文档 §23 的原始行为时，把它设为 `true` 即可 —— Token 相关代码仍在。

> **权衡**：关闭后唯一的屏障是"仅监听 127.0.0.1"，本机任何进程（含浏览器网页）都能驱动 Bridge。

## 壁纸：按设备真实能力服务，不再"假成功"

这是本版最重要的一条原则：**判断壁纸是否设置成功，只能看屏幕**。API 返回成功、dumpsys 显示成功、应用日志打印成功 —— 都不算数。本项目实测到**两次假成功**。

| 设备 | 自动设桌面 | 自动设锁屏 | 相册保存 |
|---|---|---|---|
| 华为 Android (EMUI) | ✅ 实测生效 | ❌ | ✅ |
| 鸿蒙 (HarmonyOS NEXT) | ❌ | ❌ | 经配套应用 ✅ |

华为锁屏之所以不行：EMUI 的锁屏壁纸由华为主题引擎渲染，其 provider 受 signature 级权限保护。
鸿蒙之所以不行：`setWallpaper` 在 API 26 上是**报成功但不做事**的存根，而真正的服务需要系统级权限。

面板因此会**按设备能力自适应**按钮文案，并在不支持的设备上如实拒绝，而不是返回一个用户永远看不到的成功。

## 新增：鸿蒙配套应用（`apps/harmony-helper`）

鸿蒙上通往可用壁纸的唯一链路：

```
面板「保存到相册」→ Bridge 裁剪并保留图片
   → hdc rport 反向端口转发，手机可达主机
   → 手机端「PSMW 壁纸助手」下载图片
   → 用户点 SaveButton（鸿蒙安全控件，免权限）存入相册
   → 用户在相册里「设为壁纸」
```

**已实测验证**：应用取到 20224 字节，媒体库能查到该资源，回读的 sha256 与 Bridge 裁剪产物逐字节一致，最终设置成功。

配套应用源码在 `apps/harmony-helper`，需自行构建（见该目录与根 README 的说明）。

## 其他

- 「保存到相册」从"设壁纸"流程里拆出 —— 之前它先存后设，设壁纸失败会把**已成功的保存报成错误**
- Bridge 新增 `GET /api/v1/wallpaper/latest-image`，供手机端应用下载
- 安装包改为 per-user，**自动部署 Photoshop 面板**到 UXP 旁加载目录，装完重启 PS 即在「增效工具」菜单
- `/health` 返回真实程序集版本（之前是硬编码的 `1.0.0`，导致无法判断运行的是哪个版本）

## 验证

单元测试 132 项、集成测试 14 项（两台真机，无跳过），另有 3 个端到端脚本覆盖设备识别、WebSocket 事件、全部裁剪模式与壁纸流程。

## 仍然不支持

- **其他 Android 品牌的锁屏**：未验证，一律报不支持
- **华为/鸿蒙的自动设锁屏**：见上表，需在手机相册里手动完成
- **鸿蒙应用未随安装包分发**：它需要用你自己的华为账号签名（签名 profile 绑定设备），请参照 README 自行构建
